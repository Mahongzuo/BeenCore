# BeenCore v0.2 计划（草案，待一起确认）

三件事：**补记过去**、**让地图不再空**、**为离开的亲人和宠物留一个位置**。

---

## A. 补记过去：相册、地图、整理方式

### A1. 从相册补记（最重要）

很多人的过去都在相册里，而且每张照片本来就带着时间和地点（EXIF）。

**流程**

1. 「留下印记」旁边加一个入口：**从相册补记**。一次最多选 50 张。
2. 读出每张照片的拍摄时间（`DateTimeOriginal`）和 GPS 坐标。
3. 自动分组：**同一天、相距 1km 以内**的照片归成一个「时刻」。
4. 展示一列草稿卡片，例如「找到 7 个时刻」。每张卡片已经填好照片、日期和地名，用户只需要（可以不）写一句话、选章节。
5. 「全部盖印」一次保存，或者逐张保存、跳过。

**细节**

- 没有 GPS 的照片：让用户在地图上点一下补地点，或者不记地点。
- 没有拍摄时间的照片：退回文件时间，并标成「记不清」精度。
- 照片压缩到长边 2048px 再存（expo-image-manipulator），同步和导出都更轻。
- 地名查询要限速；同一个 geohash-6 只查一次。
- 技术：原生用 `expo-image-picker`（`exif: true`），Android 读 GPS 需要 `ACCESS_MEDIA_LOCATION` 权限；Web 用 `exifr` 解析。具体字段在实现时实测确认。

**不做的**：后台扫描整个相册、自动生成印记。这类功能对隐私打扰太大，也违背「每一枚印记都是自己选的」。

### A2. 点地图任何位置创建（找回旧版的功能）

- **长按**地图任意位置 → 落一枚临时图钉，旁边显示「在这里留下印记」。
  （单击已经用来选中印记和关闭卡片，所以用长按。）
- 进入编辑页时地点已经填好，时间选择器默认展开，因为在别处补记的多半是过去的事。
- 谷歌地图和纸上地图都支持。纸上地图把点击位置反算回经纬度。
- 这样创建的印记**不能签地点墙**：只有人真的在那里，才算「来过」。

### A3. 第二个 Tab：「印记」（参考旧版「故事 / 足迹 / 人生时刻」）

把现在的「本周」升级为「印记」，顶部三个视图：

| 视图 | 内容 |
| --- | --- |
| **全部** | 所有印记，可以排序和筛选（见下） |
| **本周** | 现在的周页，原样保留 |
| **地点** | 按地点分组：「伦敦 · 23 枚」「上海杨浦 · 6 枚」，点进去是这个地方的所有印记 |

**全部视图的排序与筛选**

- 排序：发生时间（新→旧 / 旧→新）、写下时间。
- 筛选片：章节、有照片、补记的旧事（精度为年/月）、封存中、签过墙的、和某个人有关的（见 C）。
- 日期范围：沿用旧版「点起点、再点终点」的交互。
- **搜索**：在内存里匹配文字、地名和墙上那句话，离线可用；封存中的印记不会被内容搜到。（一个人的印记以千计，不需要数据库全文索引。）

**旧版有、但不搬过来的**：「足迹」的自动记录（后台定位）。它耗电，审核严，也会让地图被无意义的点淹没。印记应该是主动留下的。

## B. 谷歌地图上的景点故事（只读，按需请求）

### 能做什么

在谷歌地图上显示景点、公园、地标（其余商户继续隐藏）。点开一个景点，底部抽屉分成两块：

1. **Been 里的痕迹**：你在这里的印记、这面地点墙上的人数和留言、历史人物。
2. **在 Google 地图上**：这个景点的游客照片和评论。

**交互上的细节**

- 用户可以把印记「关联到这个景点」。我们只保存 `place_id`（谷歌明确允许永久保存），不保存名字、照片、评论。

### 能拿到多少（对照谷歌地图网页）

用户不用登录，App 用自己的 API key 请求。

| 网页上看到的 | 官方接口 |
| --- | --- |
| 总评分、评价总数（4.7 / 2,847） | ✅ |
| 照片 | ✅ 每个地点最多 10 张 |
| 评价：作者、星级、时间、正文 | ✅ 每个地点最多 5 条（按相关度） |
| 完整评价列表、排序、话题标签、视频 | ❌，用「在 Google 地图中查看全部」跳转 |

**不抓取网页版谷歌地图。** 违反服务条款，key 和 IP 会被封，App 可能被下架；评价里还有他人的个人信息。

### 两种接法

1. **Places UI Kit（第一版推荐）**：谷歌官方的「地点详情」组件，自带评分、照片、评价和全部合规署名；iOS / Android / Web 都有；官方称比直接调 API 更省钱；可以用在非谷歌地图上（纸上地图也许能用，实现时实测）。缺点：外观只能调颜色和字体。
2. **直接调 Places API**：版面完全按 Been 的风格设计，但下面的合规规则要自己一条条做到。

### 必须遵守的规则（Google Places 政策）

- 只能**实时请求、不能缓存**（`place_id` 除外）。这正好就是你说的「请求模式」。
- 必须显示 **Google 标志**；每张照片、每条评论都要带作者信息，并且链接回 Google 地图。
- 必须**和 Been 自己的内容在视觉上分开**（边框或底色），不能混在一起，也不能让人以为是 Been 用户写的。
- 要写清楚评论的排序方式（默认按相关度）。
- 地图上显示的 Places 数据，底图必须是谷歌地图。所以**纸上地图（离线）下没有这块内容**。

### 费用（按次计费，每月有免费额度）

| 内容 | 计费项 | 免费额度/月 | 超出后单价 |
| --- | --- | --- | --- |
| 照片列表 | Place Details Essentials (IDs Only) | 不限 | 免费 |
| 加载每一张照片 | Place Details Photos | 1,000 次 | $7 / 千次 |
| 评论 | Place Details Enterprise + Atmosphere | 1,000 次 | $25 / 千次 |

**控制成本的设计**

- 默认只加载 3–4 张小尺寸照片；评论放在「看看游客写了什么」后面，点了才请求。
- 估算：1,000 次「打开景点并看评论」，大约花 25 美元（评论）加 28 美元（4 张照片），共约 53 美元。在免费额度以内是 0。
- 请求从 App 直接发往 Google，API key 绑定 App 的包名和网站域名。不需要经过我们的服务器，也就不会给服务器增加成本。

### 一个提醒

谷歌评论的语气通常是「咖啡不错，四星」，和 Been 的印记很不一样。所以设计上要让它更像「窗外的世界」：一个小抽屉，照片为主，评论收起；而不是 Been 自己的内容。这样 App 不会空，Been 也不会被稀释。

## C. 亲友与宠物：他们的传记，和公开的纪念

### C1. 档案（本地，私密，默认）——内容与「我」隔离

> 11-01 第二轮调整：亲友与宠物是**独立的档案**，像旧版一样，不和自己的故事混在一起。

- 每枚印记有一个归属 `ownerId`：`null` 表示「我」，否则属于某份档案。
- 「我」的地图、印记 Tab、传记只显示自己的印记。
- 每份档案有自己的地图、印记列表和传记，同样可以导出成书。
- 地图图层里可以选「也显示亲友的印记」。


新增实体 **Person**（人或宠物）：

```ts
interface Person {
  id: string;
  kind: 'person' | 'pet';
  name: string;
  relation: string | null;   // 外婆、我的猫……
  species: string | null;    // 宠物：猫、狗……
  born: { at: number; precision: DatePrecision } | null;
  died: { at: number; precision: DatePrecision } | null;
  portraitPhotoId: string | null;
  bio: string | null;
  restingPlace: Place | null; // 安葬或撒骨灰的地方，可选
  visibility: 'private' | 'memorial';
  createdAt: number; updatedAt: number; deletedAt: number | null;
}
// Trace 增加：ownerId: string | null   // null = 我；否则属于这份档案
```

- 在档案里写印记，默认归属这份档案；也可以在编辑页切换归属。
- 「传记」Tab 顶部分成两栏：**我的** / **他们**（档案列表）。

### C2. 公开纪念（需要服务端，最后做）

只有**已离世的人**和**宠物**可以设为公开纪念。在世的人只能私密：防止有人给活人建「纪念页」骚扰对方。

公开后：

- **纪念页**：头像、名字、生卒、一段话，以及**主人挑选的**几枚印记。不是全部；印记里可能提到在世的人。
- **地图上的纪念印**：在安葬地或主人选的地方，其他用户能看到一枚不同样式的印（例如墨色单圈）。
- **一个可以分享的网页链接**：家里不用 App 的长辈也能打开看。Web 版现成就能做。
- **没有任何互动**：不献花、不留言、不计数。纪念页只是安静地记下「他们来过」。
- 举报入口收在「更多」菜单里（公开内容必须有，应用商店审核要求），3 次自动隐藏，人工复核。

### 关于费用（11-01 确认）

谷歌地图平台按开发者的 key 计费，**不能让用户用自己的谷歌账号付费**。所以第 3 阶段走零成本路线：

- 手机：Maps SDK 地图加载免费、不限量；点景点得到的名字和 ID 免费。
- 照片和评价：跳转到用户自己的 Google 地图 App 查看（Maps URLs，免费，不需要 key）。
- 网页：谷歌网页地图每月 1 万次免费后收费，所以网页版默认使用纸上地图。
- 以后有资金再内嵌官方 UI Kit，开启时在 Cloud Console 设每日用量上限，超出自动停用。

### 需要你准备的：谷歌 API key（阶段 3 开始用）

1. 在 Google Cloud Console 新建项目并开通结算（有每月免费额度）。
2. 启用：Maps JavaScript API、Places API (New)、Places UI Kit、Maps SDK for Android、Maps SDK for iOS。
3. 建两个 key：
   - Web 用：限制为你的网站域名，开发时加上 `localhost`。
   - 手机用：限制为 App 的包名 `app.been.core`。
4. 填进 `apps/mobile/.env`（见 README）。
