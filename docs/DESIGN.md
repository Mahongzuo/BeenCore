# BeenCore 设计说明

> 让世界记得你来过。

这份文档记录重构时做的每一个决定，以及为什么这样做。以后想改方向时，先看这里。

---

## 1. 一句话定位

**Been 只做一件事：记录一个人在什么时候、什么地方、留下了什么。**

旧版 Been 有抽卡、修行打卡、小游戏、资讯、信息流……它们是为了“留存”加上去的，却把用户拉向了「玩」，而不是「留下痕迹」。这一版把它们全部拿掉。

---

## 2. 功能取舍

### 保留并重做

| 功能 | 新的形态 | 为什么 |
| --- | --- | --- |
| 故事 | **印记（Trace）**：一句话 + 可选照片，自动带上时间和地点 | 全应用唯一的核心实体 |
| 地图 + 时光机 | **地图 + 时光滑轨**：一年一格的尺子，刻度高低是那年的印记数 | 旧版时光机是 800 多行的日历弹窗；回看人生只需要「选一年」 |
| 来过墙 | **地点墙**：「你是第 N 位来过这里的人」+ 历史人物 + 一句话留言 | 整个项目最打动人的想法 |
| 周页 | **本周**：七天一页，「留一件小事」 | 轻、克制，是唯一的日常入口 |
| 人生传记 | **传记**：一年一章，自动装订 | 写的人现在得不到回报，传记是给未来的回报 |
| 摇故事 | **那年今日** | 真实的回忆比随机更有分量 |

### 新增

| 功能 | 说明 |
| --- | --- |
| 补记旧事 | 时间可以只精确到「年」或「月」——人对旧事常常只记得是哪一年 |
| 时光胶囊 | 印记可以封存 1/5/10 年，到期前在任何地方都不显示内容 |
| 离线导出 | 传记导出为单文件 HTML（照片内嵌），档案导出为 JSON。不需要 Been 也能打开 |
| 停服承诺 | 写在「我」页面：停服前至少 90 天通知并提供完整导出 |
| 纸上地图 | 没网或没配谷歌 key 时，用海岸线 + 经纬网画一张离线地图 |

### 删除

抽卡 / 卡片 / 融合 / 出战、修行打卡（吃药/经期/锻炼/学习/游戏）、事件与奇思草稿、休闲小游戏 / 史莱姆、资讯 / 今日历史、关注 / 粉丝 / 点赞 / 评论信息流、AI 合影 / 年龄穿越 / 景区融合 / 视频、3D / 3DGS、真实 / 虚拟双身份、邀请。

AI 生成内容被删掉的原因不只是成本：**在一个 AI 能无限生成内容的时代，「一个真实的人真的在这里存在过」会越来越珍贵**。Been 的价值正在于此，混入生成的画面会稀释它。

## 3. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 客户端 | **Expo SDK 58（React Native 0.88）+ TypeScript + Expo Router** | 一套代码覆盖 iOS / Android / Web；你熟悉 JS / React；EAS Update 可以热更新修 bug |
| 地图 | 原生：**react-native-maps（Google 引擎）**；Web：**@vis.gl/react-google-maps**；兜底：**纸上地图（SVG）** | 对外是同一个 `<TraceMap>` 组件，按平台自动选择 |
| 本地存储 | **expo-sqlite**（原生 + Web 的 WASM/OPFS）| 本地优先：所有数据先落本机，离线完整可用 |
| 照片 | 原生：文档目录文件；Web：SQLite blob | 浏览器没有可靠的文件系统 |
| 后端 | **Hono + Cloudflare Workers + D1（SQLite）+ R2** | 无人使用时接近 0 元，小规模约 5 美元/月；Hono 可迁移到任意 Node 服务器 |
| 登录 | Google / Apple ID Token → 自有会话 JWT | 服务端不存邮箱和昵称，只知道「是同一个人」 |
| 共享逻辑 | **packages/core**：零依赖 TypeScript | 类型、geohash、同步合并、传记装订、邮戳几何、导出，三端共用，用 `node --test` 测试 |

### 为什么不是 Flutter

BeenGlobal 用过 Flutter。它失败的原因不在框架，而在照搬了旧版的功能清单。这次换成 Expo，是因为你本来写 JS/React，旧后台也是 React；不用换语言，开发更快。

### 谷歌地图的费用

- iOS / Android 地图加载：**免费、不限量**。
- Web 地图（Dynamic Maps）和地理编码：按量计费，有每月免费额度。
- 手机端的地名用系统自带的逆地理编码（免费）；Web 端有 key 才调用 Google，没有就退回离线城市表。

### 离线的边界

谷歌地图的条款不允许 App 自行缓存地图瓦片，所以**离线时底图可能看不全**。这正是纸上地图存在的原因：离线时你的印记、时间线、传记、写新印记，全部照常可用。

## 4. 视觉语言：邮戳

邮戳是「某地 + 某日 + 我经过这里」的凭证，正是「来过」的意思。

- **纸**：白天是暖白纸 `#F5F4EE`；夜间是夜墨 `#13161C`。
- **墨**：白天近黑的暖墨 `#1F1E1B`；夜间米白 `#E8E6DF`。
- **印泥**：白天是陶土红 `#AE5136`（很多国家邮局的注销墨就是红色）；夜间是护照章的紫 `#A898F2`。全应用唯一的强调色，**只属于你自己的痕迹**和主操作。
  陶土色特意比常见的 `#D97757` 压深一点，按钮上的白字才能达到可读的对比度（约 5:1，作为文字时也在 4.7:1 以上）。
- **字体**：Archivo（界面、邮戳）+ Literata（用户写下的话）。中文回落到系统字体。
- **唯一的主动动效**：盖章——印章从上方落下、压一下。其余动效都只回应用户的操作。

颜色与邮戳几何定义在 `packages/core/src/design.ts`，App 和导出的 HTML 书共用，保证风格一致。

## 5. 数据模型

只有一个核心实体：

```ts
interface Trace {
  id: string;              // 时间有序 id，离线生成不冲突
  text: string;
  happenedAt: number;      // 发生的时间，不是写下的时间
  precision: 'day' | 'month' | 'year';
  place: { lat, lng, name?, country? } | null;
  placeKey: string | null; // geohash-6（约 1.2km × 0.6km），地点墙的格子
  theme: 'everyday' | 'journey' | 'growth' | 'study' | 'work' | 'family' | 'love' | 'farewell';
  visibility: 'private' | 'wall';
  wallNote: string | null; // 签在墙上的一句话（≤ 60 字）
  wallSeq: number | null;  // 「第 N 位」，离线时为空，联网后补签
  opensAt: number | null;  // 时光胶囊
  photoIds: string[];
  createdAt, updatedAt, deletedAt; // deletedAt 是墓碑，同步需要知道「删了」
}
```

周页、传记、那年今日、时光滑轨，都是它的不同视图。

## 6. 同步协议

- 每次本地写入同时进 `outbox`（同一实体只保留最新快照）。
- `POST /sync` 推送；服务端为每次写入分配单调递增的 `seq`。
- `GET /sync?since=seq` 增量拉取。
- 冲突：`updatedAt` 晚者胜。后写胜出写在 SQL 的 `ON CONFLICT ... WHERE` 里，天然原子、天然幂等。
- 照片与地点墙签名在同一轮同步里补传、补签。

## 7. 地点墙的隐私

- 一面墙是一个 geohash-6 格子，不精确到门牌。
- 墙上只显示那一句话、季节和序号，**永远不显示名字**。
- 必须真的在那一格里才能签名（服务端校验坐标）。
- 举报 3 次自动隐藏；可以屏蔽某条留言的作者（客户端永远不知道作者是谁）。
- 删除账号会清掉所有同步数据、照片和留言；墙上的人数保留，但不再关联任何身份。

## 8. 历史人物种子

来自 Wikidata（CC0，可自由使用）：在某座城市出生或去世、维基百科语言版本 ≥ 50 的人物。目前 18 座城市、386 人，88KB，随 App 离线打包。用 `tools/build-seeds.mjs` 增加城市。

## 9. 路线图

**已完成（v0.1）**
- 本地优先的完整记录：印记、照片、补记旧事、章节、时光胶囊
- 地图 + 时光滑轨（谷歌地图 / 纸上地图）
- 本周、那年今日、传记、导出（HTML 书 + JSON 档案）
- 地点墙：序号、历史人物、留言、我也是、举报、屏蔽
- 同步引擎与后端（含开发者登录）
- 中英双语、浅色 / 深色

**下一步**
1. 真正的 Google / Apple 登录（需要在两家开发者后台创建客户端 ID）
2. 从档案包导入（换手机、或从导出文件恢复）
3. 时光胶囊到期提醒（本地通知）
4. 「继承人」：指定某人在某个条件下能读到你的传记
5. 更多城市的历史种子；按街区而不是按城市的种子
6. 原生端打包（EAS Build）与上架
